# Remotion Visual QA Agent

Automates visual quality assurance for Remotion compositions by rendering key frames directly with `remotion still`.

**Input**: Composition ID (e.g., `AIDevProductivity`, `DynamousAI`)
**Output**: `out/<CompositionId>/qa-report.md` + frames in `out/<CompositionId>/qa-screenshots/`

## Process

### Step 1: Parse Arguments

Extract composition ID from `$ARGUMENTS`. Check for flags:
- `--quick`: 2 checkpoints per scene (start, mid) instead of 4
- `--frames-file <path>`: Use pre-calculated frames from JSON file (generated by Phase 4)

**Priority order for frame selection:**
1. If `--frames-file` specified → use those exact frames
2. If `src/<CompositionId>/qa-frames.json` exists → use those frames (Phase 4 output)
3. Otherwise → calculate from timing.ts (quick or normal mode)

### Step 2: Validate Composition Exists

1. Read `src/Root.tsx` and search for the composition ID
2. If not found, list available compositions and STOP

### Step 3: Load Frame Selections

**Option A: Use qa-frames.json (preferred)**

Check if `src/<CompositionId>/qa-frames.json` exists. If so, read the frames directly:

```json
{
  "compositionId": "DynamousAI",
  "frames": [
    { "frame": 0, "scene": "intro", "reason": "scene-start" },
    { "frame": 144, "scene": "preview", "reason": "peak-content" },
    { "frame": 258, "scene": "hook", "reason": "transition" },
    { "frame": 400, "scene": "hook", "reason": "animation-cluster" }
  ]
}
```

These frames were intelligently selected by Phase 4 based on actual animation keyframes.

**Option B: Calculate from timing.ts (fallback)**

If no qa-frames.json exists, read timing.ts:
```
src/<CompositionId>/constants/timing.ts
```

Extract:
- `SCENES` object (scene names with start/duration)
- `TOTAL_FRAMES`
- `FPS` (usually 30)
- `TRANSITION_DURATION` (usually 15)
- `AUDIO_OFFSET_FIRST` / `AUDIO_OFFSET_REST`

### Step 4: Calculate Checkpoint Frames (if no qa-frames.json)

For each scene, calculate checkpoint frames:

**Normal mode:**
```
checkpoints = [
  scene.start,                                    # Scene entry
  scene.start + AUDIO_OFFSET,                     # After audio offset
  scene.start + floor(scene.duration / 2),        # Mid-scene
  scene.start + scene.duration - TRANSITION - 5,  # Before transition
]
```

**Quick mode (`--quick`):**
```
checkpoints = [scene.start, scene.start + floor(scene.duration / 2)]
```

### Step 5: Render Frame Screenshots

Create output directory:
```bash
mkdir -p out/<CompositionId>/qa-screenshots
```

Render each checkpoint frame using Remotion's `still` command:
```bash
npx remotion still <CompositionId> out/<CompositionId>/qa-screenshots/frame-<FRAME>-<SCENE>.png --frame=<FRAME>
```

**Note**: First frame takes longer (bundling). Subsequent frames are faster.

For efficiency, render all frames in sequence:
```bash
for frame in <frame_list>; do
  npx remotion still <CompositionId> out/<CompositionId>/qa-screenshots/frame-${frame}-<scene>.png --frame=${frame}
done
```

### Step 6: Analyze Each Screenshot

For each captured screenshot, read the image and analyze for:

#### Visual Checks
- [ ] **No overlapping elements** - Text and UI elements don't visually overlap
- [ ] **Text readable** - Good contrast, appropriate size, not cut off
- [ ] **No cut-off content** - All elements fully visible within frame
- [ ] **Background rendered** - No black frames, missing backgrounds, or render failures
- [ ] **Colors correct** - No unexpected color shifts, gradients render properly

#### Layout Checks
- [ ] **Elements aligned** - Grid alignment, consistent margins
- [ ] **Spacing consistent** - No unexpected gaps or crowding
- [ ] **Responsive layout** - Elements positioned correctly for composition dimensions

#### Animation State Checks
- [ ] **Correct phase content** - Only expected elements visible for this frame timing
- [ ] **No ghosting** - Previous phase content fully removed
- [ ] **Transition clean** - No artifacts during scene transitions

#### Mandatory Elements
- [ ] **BrandWatermark visible** - Check corners for watermark (may only be visible at certain intervals)

### Step 7: Generate Report

Write findings to `out/$ARGUMENTS/qa-report.md`:

```markdown
# Visual QA Report: $ARGUMENTS

**Generated**: <timestamp>
**Total frames checked**: <count>
**Composition duration**: <TOTAL_FRAMES / FPS> seconds

## Summary

| Status | Count |
|--------|-------|
| ✅ Pass | X |
| ⚠️ Warning | X |
| ❌ Fail | X |

**Overall**: ✅ PASS / ⚠️ WARNINGS / ❌ ISSUES FOUND

## Scene-by-Scene Analysis

### Scene: <name> (frames <start> - <end>)

#### Frame <N> ✅
No issues detected.

#### Frame <N> ⚠️
- **Issue**: <description>
- **Screenshot**: `qa-screenshots/frame-<N>-<scene>.png`
- **Suggested fix**: <recommendation>

...

## Frames Requiring Attention

| Frame | Scene | Issue | Priority |
|-------|-------|-------|----------|
| 258 | hook | Overlapping text | High |
| 1114 | problem | Low contrast | Medium |

## Next Steps

1. Review flagged frames in Remotion Studio
2. Fix issues in scene components
3. Re-run `/remotion-qa $ARGUMENTS` to verify
```

## Output Contract

After writing `out/$ARGUMENTS/qa-report.md`, return to main context ONLY:

```
QA Complete: X/Y frames passed. N critical issues.
Full report: out/<CompositionId>/qa-report.md
```

Or on full pass:
```
QA Complete: X/X frames passed. No issues found.
Full report: out/<CompositionId>/qa-report.md
```

**Do NOT return PNG image data or full analysis to main context.** All details are in the written report. The main context agent can read the report file if needed for debugging.

## Quick Mode

For faster validation (scene starts + midpoints only):
```
/remotion-qa <CompositionId> --quick
```

This captures ~2 frames per scene instead of ~4.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| "Composition not found" | Check spelling; IDs are case-sensitive |
| First frame slow | Normal - bundling happens once, subsequent frames fast |
| Font warnings | Ignore - doesn't affect output quality |
| Out of memory | Use `--quick` mode for large compositions |

## Integration with Workflow

Run this agent after Phase 4 (Sync) and before Phase 5 (Render):

```
Phase 4: Sync → remotion-qa-agent → [Fix issues] → Phase 5: Render
```

This catches visual issues before the expensive full render step. The agent's isolated context means PNG images never consume the main conversation's token budget.
